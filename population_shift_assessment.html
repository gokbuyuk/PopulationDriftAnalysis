Is the model transferable? Comparing a training population with an unlabelled new population

A label-free, statistically rigorous protocol for a LightGBM model trained on 20 features, to decide whether a new population (no ground truth available) is similar enough for the model to be used as is, used with caution, or not used.

1. Scope and what can (and cannot) be concluded without labels

Distribution shift comes in three forms. Without target labels only some of them can be assessed:

Shift typeDefinitionDetectable without labels?Methods in this document
Covariate shiftP(X) changes, P(y|X) unchangedYesSections 5–9
Label (prior) shiftP(y) changes, P(X|y) unchangedYes, estimableBBSE (Section 9.3)
Concept shiftP(y|X) changesNoNone. Requires labels.
Fundamental limitation. All label-free methods assume the relationship between features and target is unchanged. If the outcome mechanism differs in the new population, features can look identical and the model can still fail. A "similar population" conclusion therefore means "no evidence of covariate or prior shift that would degrade the model", not "the model is proven to perform well". Whenever feasible, label a small random target sample to verify the conclusion.
Recommended order: preconditions → baseline null → univariate tests → joint tests → out-of-support check → model-centric checks → label-free performance estimate → decision. Write the decision thresholds (Section 10) before looking at target results.

2. Preconditions and data hygiene

  1. Schema parity: same 20 columns, dtypes, units, encodings, category levels, and missing-value coding (e.g. -999 vs NaN). Many apparent shifts are pipeline differences.
  2. Same preprocessing: apply the source-fitted transformations to the target. Never refit them on the target or on pooled data.
  3. Source split usage: use the source holdout/test set (not training rows) as the reference for model-based checks. Training rows carry optimistic, overfitted scores.
  4. Remove leakage columns from joint tests: IDs, timestamps, row order, batch identifiers.
  5. Representativeness: confirm the target sample is a random/representative draw of the population where the model will be used.
  6. Reproducibility: fix and log a seed; record dataset hashes, row counts, and code version.

3. The baseline: build a source-vs-source null distribution

Fixed rule-of-thumb thresholds ignore sample size and the feature's natural variability. The most defensible baseline is the amount of "drift" observed between two random samples of the same (source) population. Any target statistic should be compared to this reference.

Procedure

  1. Repeat B times (e.g. B = 200–1000, fixed seed): draw a random subset of the source of size ntarget (sample A) and use the remaining source rows (sample B).
  2. Compute every statistic used below (KS D, PSI, Wasserstein, SMD, classifier AUC, score PSI, ...) for A vs B.
  3. The null threshold for each statistic is its empirical 95th (or 99th) percentile.
  4. Empirical p-value for the target statistic T: p = (1 + #{null ≥ T}) / (1 + B).

Matching the size to ntarget matters because many statistics (KS D, PSI, AUC from a finite classifier) are biased upward in small samples.

Optional: an operational tolerance baseline

If the source has a time dimension, compute the same statistics between the source training window and later source periods where the model was known to perform acceptably. That gives a practical tolerance: target drift inside this range has already been shown not to break the model.

Target statistic relative to baselineInterpretation
≤ 95th percentile of source-vs-source nullIndistinguishable from sampling noise → similar on this metric
> null 95th percentile but ≤ operational toleranceReal but previously tolerated difference
> bothReal and outside known safe range → investigate
Python sketch: null distribution for any two-sample statistic 
import numpy as np
import pandas as pd
from typing import Callable


def null_distribution(source: pd.Series, n_target: int,
                      statistic: Callable[[pd.Series, pd.Series], float],
                      n_rounds: int = 500, seed: int = 42) -> np.ndarray:
    """Source-vs-source null of a two-sample statistic with target-matched sample size."""
    if n_target >= len(source):
        raise ValueError(f"n_target={n_target} must be smaller than source size={len(source)}.")
    rng = np.random.default_rng(seed)
    values = np.empty(n_rounds)
    for i in range(n_rounds):
        order = rng.permutation(len(source))
        values[i] = statistic(source.iloc[order[:n_target]], source.iloc[order[n_target:]])
    return values


def empirical_p_value(observed: float, null_values: np.ndarray) -> float:
    """One-sided permutation-style p-value: P(null ≥ observed)."""
    return (1 + np.sum(null_values >= observed)) / (1 + len(null_values))

4. Statistical principles: significance, effect size, and equivalence

4.1 Significance alone is not a decision criterion

With thousands of rows, almost every test rejects H0 ("same distribution") even for trivial differences. With few rows, real differences go undetected. Always report three things per feature:

  1. p-value (is there a difference at all?), corrected for multiple testing;
  2. effect size with a bootstrap 95% CI (how large is it?);
  3. position relative to the source-vs-source null (is it larger than natural variability?).

4.2 Multiple comparisons

Testing 20 features at α = 0.05 gives roughly a 64% chance of at least one false positive if nothing changed (1 − 0.9520 ≈ 0.64). Correct the p-values:

  • Benjamini–Hochberg (FDR), recommended for screening many features;
  • Holm (FWER), when any single false alarm is costly.

Report how many tests were run in total, not only those that were significant.

4.3 "Not significant" ≠ "similar": use equivalence testing

Failing to reject H0 is absence of evidence, not evidence of similarity. To claim similarity, use the Two One-Sided Tests (TOST) procedure with a pre-specified equivalence margin, e.g. |SMD| < 0.1. Equivalence is concluded when the 90% CI of the difference lies entirely inside the margin.

Difference test (H0: equal)Equivalence test (H0: differ by ≥ margin)Conclusion
Not rejectedRejectedSimilar (equivalent)
RejectedRejectedStatistically different but practically equivalent (typical with large n)
Not rejectedNot rejectedInconclusive: underpowered, more data needed
RejectedNot rejectedDifferent and practically relevant
Python sketch: TOST on a feature mean with an SMD-based margin 
import numpy as np
from statsmodels.stats.weightstats import ttost_ind

pooled_sd = np.sqrt((src[col].var() + tgt[col].var()) / 2)
margin = 0.1 * pooled_sd                          # equivalence margin |SMD| < 0.1
p_equivalence, _, _ = ttost_ind(tgt[col].dropna(), src[col].dropna(),
                                -margin, margin, usevar="unequal")
# p_equivalence < 0.05  ->  means are equivalent within ±0.1 SD

5. Univariate feature tests (one per feature, 20 features)

Legend: statistical = formal test with a p-value; heuristic = convention, not a statistical test. Use heuristics only alongside the Section 3 baseline.

5.1 Continuous features

MethodH0 / what it measuresInterpretationRule of thumb
Kolmogorov–Smirnov two-sample statistical Same distribution. D = max |ECDFs − ECDFt| ∈ [0, 1]. Sensitive to shifts near the median, weak in the tails. Invalid p-values with many ties/discrete values. D < 0.1 negligible, 0.1–0.2 moderate, > 0.2 large heuristic. Prefer the null baseline.
Anderson–Darling k-sample statistical Same distribution. Tail-weighted ECDF distance. More powerful than KS for tail differences (often what matters for risk models). SciPy's p-value is capped to [0.001, 0.25]; use a permutation p-value if finer resolution is needed. Use p-value (BH-corrected) + null baseline.
Cramér–von Mises two-sample statistical Same distribution. Integrated squared ECDF difference. Sensitive to differences across the whole distribution, not only the maximum gap. Use p-value + null baseline.
Wasserstein-1 (Earth Mover's) distance Effect size in the feature's units: average "transport" needed to turn one distribution into the other. Interpretable magnitude. Divide by source SD or IQR to compare across features. Normalized W < 0.1 small, 0.1–0.25 moderate, > 0.25 large heuristic. Bootstrap CI.
Standardized Mean Difference (SMD) (μt − μs) / √((σ²s + σ²t)/2) Location shift only. Complement with a variance ratio (σ²t/σ²s). |SMD| < 0.1 balanced (Austin 2009); Cohen: 0.2 small, 0.5 medium, 0.8 large. Variance ratio outside [0.5, 2] = notable.
Population Stability Index (PSI) heuristic Σ (qi − pi) · ln(qi/pi) over bins (source quantile deciles). Industry-standard, symmetric KL-type divergence. Depends on binning and grows with small n. Report bins used. < 0.10 stable; 0.10–0.25 moderate shift; > 0.25 major shift (Siddiqi 2006). Compare to the null baseline.

5.2 Categorical / binary / low-cardinality ordinal features

MethodH0 / what it measuresInterpretationRule of thumb
Chi-square test of homogeneity statistical Same category proportions (2 × k table). Requires expected counts ≥ 5 per cell. Otherwise merge rare levels or use Fisher's exact / a permutation test. p-value (BH-corrected).
Cramér's V Effect size for the chi-square test, ∈ [0, 1]. For a 2 × k table (df* = 1), Cohen's scale applies directly. 0.1 small, 0.3 medium, 0.5 large (Cohen 1988).
Jensen–Shannon distance (base 2) Symmetric, bounded [0, 1] divergence between category distributions. Robust to zero cells, unlike KL divergence. < 0.1 small heuristic; use null baseline.
PSI on categories heuristic As above, with categories as bins. Same caveats; apply a small ε to empty categories. 0.10 / 0.25 thresholds.
Unseen-level rate Share of target rows with categories absent in training. LightGBM routes unseen categories down a default branch: predictions on them are unreliable. > 1% of rows warrants review heuristic.

5.3 Missingness (every feature)

MethodInterpretationRule of thumb
Two-proportion z-test (or Fisher's exact) on missing rate statistical LightGBM learns a direction for missing values. A change in missingness changes which branch rows follow, and may also indicate a different data collection process. Effect size Cohen's h: 0.2 small, 0.5 medium, 0.8 large.
Missingness co-occurrence pattern (Jaccard or a chi-square test on missingness-pattern frequencies) Detects systematic, not random, changes in what is recorded. New dominant patterns = data pipeline review.
Python sketch: univariate battery with BH correction 
import numpy as np
import pandas as pd
from scipy import stats
from statsmodels.stats.multitest import multipletests


def psi(source: np.ndarray, target: np.ndarray, n_bins: int = 10, eps: float = 1e-6) -> float:
    """PSI with source-quantile bins. Handle NaN separately (missingness test)."""
    edges = np.unique(np.quantile(source, np.linspace(0, 1, n_bins + 1)))
    edges[0], edges[-1] = -np.inf, np.inf
    p = np.clip(np.histogram(source, edges)[0] / len(source), eps, None)
    q = np.clip(np.histogram(target, edges)[0] / len(target), eps, None)
    return float(np.sum((q - p) * np.log(q / p)))


rows = []
for col in continuous_cols:
    s, t = src[col].dropna().to_numpy(), tgt[col].dropna().to_numpy()
    ks = stats.ks_2samp(s, t)
    rows.append({
        "feature": col,
        "ks_d": ks.statistic, "ks_p": ks.pvalue,
        "smd": (t.mean() - s.mean()) / np.sqrt((s.var(ddof=1) + t.var(ddof=1)) / 2),
        "var_ratio": t.var(ddof=1) / s.var(ddof=1),
        "wasserstein_norm": stats.wasserstein_distance(s, t) / s.std(ddof=1),
        "psi": psi(s, t),
    })
report = pd.DataFrame(rows)
report["ks_p_bh"] = multipletests(report["ks_p"], method="fdr_bh")[1]

6. Multivariate / joint distribution tests

Marginals can match while the joint distribution differs (e.g. age and income keep their histograms but their correlation flips). Gradient-boosted trees rely on interactions, so joint tests are essential.

6.1 Classifier two-sample test (adversarial validation) — primary test

Train a classifier (LightGBM) to predict population membership (source = 0, target = 1) from the 20 features. Use stratified K-fold out-of-fold predictions and compute the AUC (Lopez-Paz & Oquab, 2017).

  • H0: the populations are indistinguishable, so the expected AUC is 0.5.
  • p-value: permutation test (shuffle population labels, rerun CV, B ≥ 100). Alternatively, the Mann–Whitney U test on the out-of-fold scores as an approximation.
  • CI: bootstrap the out-of-fold AUC.
  • Diagnosis: SHAP importance of the domain classifier shows which features drive the separation.
  • By-product: the domain probabilities give density-ratio weights for Section 9.1.
Out-of-fold domain AUCInterpretation
≤ null 95th percentile (typically 0.50–0.55)Indistinguishable populations
0.55–0.65Mild shift. Usually tolerable if not driven by high-importance model features.
0.65–0.80Moderate shift. Weighted performance estimate (Section 9) required.
> 0.80Strong shift. Populations are largely separable; overlap is poor and transfer is risky.

These AUC bands are heuristics, loosely mirroring the Hosmer–Lemeshow discrimination scale (0.7 acceptable, 0.8 excellent, 0.9 outstanding). The permutation p-value and the null baseline are the statistical criteria. Remove ID/timestamp columns first, or the AUC is trivially ≈ 1.

The domain AUC is a global measure and can stay low while one important feature shifts materially. Example: a mean shift of SMD = 0.38 in a single feature (one of two) gave an out-of-fold AUC of only 0.55 on synthetic data. Never rely on the AUC alone; always cross it with the per-feature drift × importance table (Section 8.1).

Python sketch: classifier two-sample test with permutation p-value 
import numpy as np
import pandas as pd
from lightgbm import LGBMClassifier
from sklearn.metrics import roc_auc_score
from sklearn.model_selection import StratifiedKFold, cross_val_predict


def oof_domain_scores(features: pd.DataFrame, domain: np.ndarray, seed: int = 42) -> np.ndarray:
    """Out-of-fold P(target | x) from a LightGBM domain classifier."""
    cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=seed)
    model = LGBMClassifier(n_estimators=200, learning_rate=0.05, random_state=seed, verbose=-1)
    return cross_val_predict(model, features, domain, cv=cv, method="predict_proba")[:, 1]


features = pd.concat([src[feature_cols], tgt[feature_cols]], ignore_index=True)
domain = np.r_[np.zeros(len(src), dtype=int), np.ones(len(tgt), dtype=int)]
scores = oof_domain_scores(features, domain)
observed_auc = roc_auc_score(domain, scores)

rng = np.random.default_rng(42)
null_auc = np.array([roc_auc_score(perm, oof_domain_scores(features, perm))
                     for perm in (rng.permutation(domain) for _ in range(100))])
p_value = (1 + np.sum(null_auc >= observed_auc)) / (1 + len(null_auc))

6.2 Kernel / distance two-sample tests

MethodH0InterpretationNotes
Maximum Mean Discrepancy (MMD), RBF kernel, permutation p-value statistical Ps(X) = Pt(X) p < 0.05 = joint distributions differ. MMD² magnitude is the effect size; compare it to the null baseline. Standardize with source statistics first. Median-heuristic bandwidth. Encode categoricals. O(n²): subsample (e.g. 5k per group) and repeat across seeds. Library: alibi-detect (MMDDrift).
Energy distance test statistical Ps(X) = Pt(X) Same reading as MMD. Few tuning parameters. Permutation p-value. Library: dcor.

Use these to confirm the classifier test. If they disagree, the classifier test is usually more powerful on tabular data with mixed types; the kernel tests are more sensitive to diffuse, low-dimensional shifts.

6.3 Dependence structure

MethodInterpretationRule of thumb
Pairwise correlation difference, Fisher z-test per pair (190 pairs for 20 features), BH-corrected statistical z = (atanh rt − atanh rs) / √(1/(nt−3) + 1/(ns−3)). For Spearman ρ, use variance ≈ 1.06/(n−3) (Fieller et al., 1957). |Δρ| > 0.2 on an important pair = material heuristic.
Global correlation-matrix difference: Frobenius norm ‖Rt − Rs‖F with permutation p-value statistical A single omnibus test for a changed dependence structure. Compare to the source-vs-source null. Avoid Box's M (overly sensitive to non-normality).

7. Support and out-of-distribution (OOD) checks

Tree ensembles do not extrapolate: beyond the training range, predictions stay flat at the edge value. Rows outside the training support get confident-looking but unsupported predictions.

CheckProcedureStatistical test / baselineRule of thumb
Per-feature range coverage Share of target rows below the source 0.5th percentile or above the 99.5th percentile. Expected share under H0 = 1%. One-sided binomial test vs p = 0.01 statistical. > 2× expected (2%) on an important feature = review heuristic.
Joint novelty (Isolation Forest, or k-NN distance) Fit on source train rows; set the threshold at the 1st percentile of score_samples on the source holdout; compute the share of target rows below it. Expected ≈ 1% under H0; binomial test vs 0.01 statistical. < 2% fine; 2–5% caution; > 5% material OOD share heuristic.
Overlap of domain-classifier scores Share of target rows with P(target | x) > 0.95 (essentially no comparable source rows). Compare to the null baseline. Treat those rows as unsupported. Flag them, abstain, or route them to a fallback.
Even when aggregate tests pass, a subset of target rows can be OOD. Report the share and profile of those rows and decide on them separately (row-level guardrail).

8. Model-centric checks (does the shift matter to this model?)

8.1 Weight drift by feature importance

Compute mean |SHAP| per feature on the source holdout and cross it with the drift effect sizes from Section 5:

Low drift (within null)High drift (beyond null, non-trivial effect)
High model importance (top features covering ~80% of total mean |SHAP|)OKCritical: drives the decision
Low model importanceOKDocument; usually harmless

8.2 Prediction (score) distribution shift

MethodInterpretationRule of thumb / baseline
KS / Anderson–Darling on predicted probabilities (source holdout vs target) statistical The model behaves differently on the new population. Not necessarily worse: the case mix may simply differ. Compare to the null baseline.
Score PSI (on source score deciles) heuristic The most widely used monitoring metric in credit/risk scoring. < 0.10 stable; 0.10–0.25 monitor; > 0.25 action.
Predicted-positive rate at the operating threshold: two-proportion z-test, Cohen's h statistical Directly affects operations (volume flagged, capacity, cost). h ≥ 0.2 = operationally relevant.
Share of predictions near the decision threshold (e.g. ±0.05) More borderline cases = more expected misclassifications. Compare to the source holdout share (two-proportion test).

8.3 Attribution (SHAP) drift

  • Compare per-feature SHAP value distributions (KS test, BH-corrected) and the mean |SHAP| ranking (Spearman rank correlation between source and target importance rankings; ρ < 0.8 = noticeably different reasoning heuristic).
  • SHAP drift is more model-relevant than raw feature drift: it measures the shift through the lens of the learned function.
  • Overlay target rows on partial-dependence / ICE plots. Mass in flat (extrapolated) or sparse regions of the source is a warning sign.

9. Label-free performance estimation

These methods return estimates under assumptions, not measurements. Always state the assumption and report a CI.

9.1 Importance-weighted validation (covariate shift correction)

Assumes: covariate shift only, and overlap (every target region has some source data). (Shimodaira 2000; Sugiyama et al. 2007.)

  1. From the domain classifier (Section 6.1), compute out-of-fold p(x) = P(target | x) for source holdout rows.
  2. Density ratio: w(x) = p/(1−p) · nsource/ntarget. Clip extreme weights (e.g. at the 99th percentile) and report the clipping.
  3. Estimated target metric: weighted AUC / log-loss / Brier score on the labelled source holdout (e.g. roc_auc_score(y, pred, sample_weight=w)). Bootstrap for a CI.
  4. Compare to the unweighted source holdout metric: this is the baseline.
Kish effective sample size ratio ESS/n, ESS = (Σw)² / Σw²Reliability of the weighted estimate
> 0.5Good overlap; estimate reliable
0.1–0.5Partial overlap; wide CI, interpret with caution
< 0.1Poor overlap; estimate unreliable, and that is itself evidence against transfer

ESS bands are heuristics. The bootstrap CI width is the formal measure of reliability.

9.2 Confidence-Based Performance Estimation (CBPE)

Assumes: no concept shift, and the model is well calibrated on the source. If the model predicts p = 0.3 for a row, it is correct about 30% of the time, so the expected confusion matrix (and AUC, F1, ...) on the target can be computed from the predicted probabilities alone.

  • Prerequisite check on the source holdout: reliability diagram, Brier score, Expected Calibration Error (ECE), and calibration slope ≈ 1 / intercept ≈ 0. If the model is miscalibrated, recalibrate it (isotonic or Platt) on a separate source fold first.
  • Library: nannyml (CBPE). Its output includes confidence bands.
  • Interpretation: an estimated target metric within the source holdout CI means no expected degradation.
  • Limitation: CBPE cannot see shifts the model is confidently wrong about. Combine it with Sections 7 and 9.1.

9.3 Label (prior) shift: Black Box Shift Estimation (BBSE)

Assumes: P(X|y) unchanged (Lipton et al., 2018).

  1. On the source holdout, compute the confusion matrix Cij = P(ŷ = i, y = j).
  2. On the target, compute μi = P(ŷ = i).
  3. Solve w = C−1μ. The estimated target prior is qj = wj · Ps(y = j). C must be invertible (the model must be better than random).
  4. Bootstrap the estimate. If the 95% CI of the target prevalence excludes the source prevalence, there is significant prior shift.

Consequence: with prior shift alone, ranking (AUC) is preserved but calibration and threshold-based metrics are not. Adjust the intercept or threshold using the estimated prior.

9.4 Comparison summary

MethodKey assumptionFails when
Importance weightingCovariate shift + overlapLow ESS, concept shift
CBPECalibration + no concept shiftMiscalibration, confidently wrong regions
BBSELabel shift onlyCovariate/concept shift

If two methods agree, confidence increases. If they disagree, report both and treat the result as inconclusive.

Aggregation rule (example)

  • Use as is: no red, at most two amber signals, none on top-importance features.
  • Use with mitigation: amber signals, no red → recalibrate or adjust the threshold for prior shift, add a row-level OOD guardrail, monitor score PSI, and collect a small labelled sample.
  • Do not use as is: any red on the domain AUC, OOD share, ESS, or estimated performance → retrain or adapt (requires target labels, or at least domain-weighted retraining on source data), or restrict use to the supported subset.
All numeric thresholds above are conventions (cited where a source exists). Replace them with domain-specific tolerances where possible: e.g. "an AUC loss of 0.02 costs X". The source-vs-source null baseline is the statistically grounded reference.
Strongest possible label-free claim: "The new population is statistically equivalent to the training population on the model-relevant features within margin δ; the joint distribution is indistinguishable beyond sampling noise; X% of rows are out of support; estimated performance is M [95% CI], assuming no concept shift."

11. Reporting checklist

  • Data sources, extraction dates, row counts, and dataset hashes for both populations.
  • Source split used as the reference (holdout, not training rows).
  • Seed(s), number of bootstrap/permutation rounds, CV scheme, binning choices, kernel bandwidth, weight clipping.
  • All tests run (total count) with raw and BH-corrected p-values, effect sizes with 95% CIs, and null-baseline percentiles.
  • Pre-registered decision thresholds and equivalence margins, with their justification.
  • Per-feature drift × importance table; domain-classifier SHAP drivers; OOD share and profile.
  • Label-free performance estimates with their assumptions and CIs; agreement between methods.
  • Explicit statement: concept shift cannot be assessed without target labels.
  • Recommendation and mitigation plan: monitoring metrics, alert thresholds, and a labelling plan for a verification sample.
