Proposal: concise population drift decision

16 October 2026. Standalone approval note for deciding whether a deployed LightGBM model may score an unlabelled population with the same feature contract.

Purpose

Decide whether the deployed LightGBM model may score an unlabelled population with the same feature contract. The run measures distribution differences and combines them into a severe, moderate, or mild decision.

Required inputs

  • Fit set.
  • Optional independent evaluation set.
  • New unlabelled set.
  • Exact model feature list, categorical declarations, and missing sentinels.
  • Deployed model and label column.
  • Operating threshold and performance tolerance.

Protocol

Validate schema; build target-size-matched source baselines; run feature, joint, support, model-output, attribution, and label-free performance checks; aggregate the resulting signals.

Reference assignment

Without --test, every comparison uses the labelled set. With --test, feature, joint, and support tasks use fit versus new; score, attribution, and performance tasks use evaluation versus new; calibration uses evaluation only.

Decision rule

Severe if any counted signal is severe. Mild if no signal is severe, at most two are moderate, and no moderate signal is model-important. Moderate otherwise.

Outputs

The run writes decision.json, task tables, baseline summaries, metadata, and the generated report.

Limitation

The run measures distribution differences and estimates performance under explicit assumptions; it cannot identify concept shift or measure performance on the new population without labels.

Approval defaults

Seed 42, at least 30 baseline rounds, decision threshold 0.5 unless production differs, and performance tolerance 0.02 unless a domain-specific tolerance is approved.
