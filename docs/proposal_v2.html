Proposal: population drift assessment before transferring a LightGBM model

16 October 2026. Status: implemented in population_drift and exercised on synthetic data only. No production population has been scored. Full method detail: reports/population_shift_assessment_v2.html and docs/reference.md.

Decision and scope

Decide whether a deployed LightGBM model (binary or regression) can score a new, unlabelled population that has the same feature contract. The output is a pre-specified severe / moderate / mild verdict with a traceable signal list. severe: do not use as is. moderate: use only with review. mild: no evidence of shift that the model is sensitive to; monitor.

The run identifies covariate shift (P(x)) and, under its assumption, label shift (P(y)). It cannot identify concept shift (P(y|x)) or measure accuracy on the new population. A mild verdict is not evidence that discrimination or calibration carried over.

Approach

  1. Freeze the contract first. Feature list, categorical columns, missing sentinels, operating threshold, performance tolerance, Thresholds, and seed are fixed before the new file is summarised, so cutoffs cannot be tuned to the result.
  2. Size-matched no-shift baseline. Each of ≥ 30 rounds randomly partitions the reference into a pseudo-new subset of size nnew and a remainder, and recomputes every point statistic. These no-shift baseline values show how large each statistic gets from sampling noise alone. The statistic measured on the new dataset (the observed value) counts as shifted only if it exceeds the 95th percentile of the baseline values. Empirical p = (1 + number of baseline rounds with a value ≥ the observed value) / (1 + number of rounds). With 30 rounds the minimum is 1/31. This replaces fixed PSI/KS cutoffs, which are biased by sample size.
  3. Marginal tests per feature. Continuous: KS, Anderson–Darling, Cramér–von Mises, SMD with TOST equivalence (±0.1 SD), variance ratio, Wasserstein/SD, PSI (10 source-quantile bins). Categorical: χ² after merging sparse levels, Cramér’s V, Jensen–Shannon, PSI, unseen-level share. Missingness: two-proportion z and Cohen’s h, separate from values, because LightGBM routes missing values down a learned branch. Benjamini–Hochberg is applied within each test family.
  4. Joint distribution and support. Domain classifier: fixed-hyperparameter LightGBM, stratified 5-fold out-of-fold ROC AUC, 20 label-permutation refits. Kernel tests: MMD² and energy distance. Dependence: Spearman Frobenius norm and per-pair Fisher z. Support: share of values outside the training 0.5–99.5% quantiles, and an Isolation Forest with its threshold set on a held-out 30% training slice (expected flagged share under no shift: 1% by construction). Trees do not extrapolate, so support matters.
  5. Model-centric tests. Score KS/PSI. Positive rate and near-cutoff share (±0.05) at the deployed threshold. TreeSHAP contribution KS and rank correlation of mean |SHAP|. A model-important feature belongs to the smallest set reaching 80% of mean |SHAP|.
  6. Label-free performance estimates, kept separate. Importance weighting (assumes covariate shift; domain-classifier density ratio, clipped at the 0.99 quantile, Kish ESS). CBPE (assumes calibrated scores; downgraded to info if source ECE > 0.05). BBSE (assumes label shift, P(x|y) unchanged). If they disagree, the result is reported as inconclusive, not averaged.
  7. Aggregate by a fixed rule (below). If the verdict is not mild, label a simple random sample of the new population. That is the only test of concept shift.

The paired mode is recommended. Scores, SHAP, and calibration on the fit set are in-sample and therefore optimistic. Each reference gets its own size-matched baseline.

Verdict rule

A feature is severe only if three conditions hold together: the BH-adjusted test rejects at α = 0.05, the statistic exceeds the baseline 95th percentile, and the effect is large (PSI ≥ 0.25, KS D ≥ 0.20, or |SMD| ≥ 0.50; categorical PSI ≥ 0.25 or V ≥ 0.30; missingness |h| ≥ 0.50).

Verdict: severe if any counted signal is severe. mild if there is no severe signal, at most two moderate signals, and none of them flagged model-important. That flag is set by drift, missingness, range, or SHAP changes on an important feature, and always by a score-distribution shift. moderate otherwise. Calibration and degraded CBPE are info and are not counted.

Anticipated questions

Why not the standard PSI 0.10 / 0.25 rule?
PSI, KS D, and AUC grow as n shrinks and vary by feature. The cutoffs (Siddiqi 2006) are kept as effect-size floors, but a flag also requires significance and exceeding the size-matched no-shift baseline.
What is the false-alarm behaviour?
The verdict is a decision rule, not a level-α test, and there is no family-wise control across signals. On 10 synthetic same-distribution pairs (2,500 vs 1,000 rows, 10-round baselines) none was severe and 3 were moderate. This is indicative only, not the operating configuration. A single weak moderate is a review item.
Is the domain classifier leaky or tuned?
No. The target is population membership, never the business label. Scores are out-of-fold and hyperparameters are fixed (no search). The verdict uses the size-matched baseline and the AUC bands. The permutation p-value (minimum 1/21) is reported but does not gate. Identifiers, time columns, and score- or label-derived columns must be excluded, because they trivially separate the populations.
What does the no-shift baseline assume?
Exchangeability within the reference. Drift already present inside the reference window widens the baseline, so a further shift can look ordinary. Use a reference window over which the model is known to have performed acceptably.
Selection bias (approved-only labels, reject inference)?
Not addressed. The labelled reference is whatever population carried outcomes. If that is booked accounts and the new file is through-the-door applicants, the comparison mixes policy effects with population shift. Compare like-for-like populations.
Segments and fair-lending slices?
There is no built-in segment analysis. Run the same comparison per segment (product, channel, region) with its own baseline. Expect lower power at small n. At least 30 new rows are required.
Power limits?
Row caps: kernel tests 2,000 per group, correlations 20,000, SHAP 5,000, Isolation Forest 100,000, domain classifier 200,000 in total. A shift visible only above a cap can be missed by that task.
Sample-size requirements?
Paired mode raises an error if a reference has fewer than nnew + 30 rows. Single mode instead shrinks the baseline subset to half the reference and warns. Treat that warning as a protocol deviation.
Reproducibility and audit trail?
The seed (42), the full configuration, row counts, failed tasks, and library versions (pinned in requirements.txt) are written to metadata.json. Dataset checksums and the code commit are not recorded automatically. Log both with each archived run. A failing task is recorded in failed_tasks and does not abort the others; review that list before accepting a verdict.

Deliverables

decision.json (verdict, rule, signals with their reference pair, counts, warnings), baseline_comparison.csv, per-task tables, baseline statistics and summaries, metadata.json, and the HTML report. Data and outputs stay untracked.
