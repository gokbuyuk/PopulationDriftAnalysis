Population Shift Assessment

Detailed technical reference for deciding whether a LightGBM model fitted on a labelled reference population can be applied to an unlabelled new population.

1. Question, scope, and non-identifiability

The operational question is whether a fitted model can be transferred to a new population that has the same model inputs but no observed label. The toolkit compares observed drift statistics with source-vs-source sampling variability and aggregates the resulting signals. It does not perform one omnibus level-α test that the populations are identical, and it does not control a family-wise error rate over the final signal list.

ShiftDefinitionWhat this toolkit can establish without new labels
Covariate shiftP(x) changes while P(y|x) is unchanged.Feature, joint, support, score, attribution, and importance-weighting diagnostics can detect or estimate consequences under the unchanged-conditional assumption.
Label shiftP(y) changes while P(x|y) is unchanged.BBSE estimates the new class prior under that assumption.
Concept shiftP(y|x) changes.Not identifiable from unlabelled new rows. New labels are required.

Measurement boundary. Every value presented for performance on the new population is an estimate under stated assumptions. A mild verdict is not measured target accuracy, and disagreement between estimators is evidence of inconclusiveness rather than permission to select the most favorable estimate.

Sources: README.md; docs/reference.md.

2. Input contract and validation

  • Files: CSV, Parquet (.parquet or .pq), and Feather are supported. Missing files and unsupported extensions fail immediately.
  • Feature parity: every named feature must exist on both sides. Empty feature lists, duplicate feature names, declared categoricals outside the feature list, and a label included as a feature are rejected.
  • Feature selection: --features-file reads one feature per non-comment line; --features accepts comma-separated names. Otherwise, shared columns are used after removing the label and --exclude columns. Identifiers, timestamps, post-label fields, and score-derived fields must be excluded by the operator.
  • Categorical handling: explicitly declared columns, non-numeric columns, booleans, and numeric columns with at most 10 distinct source values are categorical. This avoids applying KS-type continuous tests under heavy ties. Values such as 1 and 1.0 are normalized to the same categorical level.
  • Missing values: comma-separated --missing-sentinels, such as -999, are replaced with missing values before analysis. A feature entirely missing in either population and incompatible numeric/non-numeric dtypes produce warnings.
  • Rows: operational decisions require at least 30 new rows. Paired mode enforces at least n_new + 30 rows in each reference. Baseline construction requires at least 30 rows in both random partitions.
  • Model and label: model tasks require a supported binary-classification or regression LightGBM model. Model files may be Booster .txt/.model or pickled/joblib estimators. Model feature names/count must match. Label-dependent tasks require the label on the source used by those tasks; binary labels must contain both 0 and 1. Regression switches the performance metrics to RMSE and MAE.

Fail-fast boundary: structural input, baseline compatibility, paired-size, model-loading, and configuration errors are raised before or at orchestration. Once task execution begins, a task-level exception is logged and recorded in metadata["failed_tasks"]; other tasks continue. Therefore, a completed run can still be incomplete and must be checked for failed tasks.

Sources: analysis.py (load_table, validate_inputs, infer_feature_types, _validate_paired, model validation); tests/test_comparison.py.

4. Target-size-matched baseline

For each round, the source is randomly permuted. The first subset_size rows act as pseudo-new data and the remaining rows act as the reference. subset_size should equal the new population size because PSI, KS D, and domain-classifier AUC depend on sample size. Baseline rounds compute point statistics but disable bootstrap and permutation inference.

The observed statistic exceeds baseline when it is strictly greater than the baseline 95th percentile. Its add-one empirical p-value is:

(1 + number of baseline values ≥ observed) / (1 + number of rounds)

At the decision minimum of 30 rounds, resolution cannot be finer than 1/31. Fewer than two rounds are rejected by the API; the documented decision setting is 30 or more. The baseline feature set must exactly match the comparison feature set. A supplied baseline emits a size warning when the new population is outside one-half to twice its subset size. In single mode, an undersized source causes an automatically built baseline to use a smaller subset and issue a warning; paired mode instead enforces exact target-size feasibility.

Assumption: exchangeability within the reference. This null captures random-partition sampling noise, not drift already present over the reference window. A moving reference can widen the null and conceal additional change. Separate fit and evaluation references in paired mode produce separate baselines before their statistics are combined.

Sources: analysis.py (build_baseline, compare_to_baseline, run_comparison, _paired_baseline); baseline test in tests/test_comparison.py.

Benjamini–Hochberg correction is applied within each p-value family across features at α = 0.05. It is not applied across the final signal list. A feature's severity is the worse of distribution and missingness severity. Severe requires significance, a statistic beyond baseline, and a large effect; moderate requires significance, baseline exceedance, and a moderate effect.

Model importance is the smallest feature set whose reference-population mean absolute TreeSHAP contributions reach 80% of total importance. A low-importance feature may remain severe in the feature table, but its aggregate feature signal is capped at moderate. Without a model, all features are treated as important.

Sources: docs/reference.md; analysis.py (assess_features, Thresholds).

6. Joint distribution and support tests

Domain classifier

A LightGBM population-membership classifier uses fixed hyperparameters: 200 trees, learning rate 0.05, 31 leaves, row and column subsampling 0.8, and L2 penalty 1. Its metric is stratified 5-fold out-of-fold (OOF) ROC AUC, so each row is scored only by a model that did not train on that row. The business label is never used. The classifier is refit after population-label shuffling for 20 permutations; the verdict uses this permutation p-value, while a stored Mann–Whitney p-value conditions on fixed scores. Rows are capped at 200,000.

Kernel, energy, dependence, and support

  • MMD and energy distance: continuous values are source-median-imputed and source-standardized; categoricals are one-hot encoded for the top 10 source levels. MMD uses an unbiased squared RBF statistic with median-heuristic bandwidth. Both use permutation p-values and at most 2,000 rows per population. They can produce at most a moderate signal.
  • Correlation: Spearman matrices are compared globally with a permutation test on the upper-triangle Frobenius norm. Per-pair changes use Fisher z with variance 1.06/(n−3) and Benjamini–Hochberg correction. At most 20,000 rows are used.
  • Range coverage: each continuous feature is checked against source 0.5%–99.5% quantiles and source min/max. A one-sided binomial test asks whether the expected tail share is exceeded.
  • Joint support: Isolation Forest is fit on 70% of source rows. The 1% score quantile on the held-out 30% defines the out-of-support threshold, making the null share 1% by construction. A one-sided binomial test evaluates the target share. At most 100,000 rows are used.

Sources: docs/reference.md; implementations in analysis.py.

7. Model-centric tests

  • Score distribution: KS and source-bin PSI compare model scores. Baseline position gates score-severity interpretation.
  • Operating impact: at decision_threshold (default 0.5), the predicted-positive rate is compared by two-proportion z-test and Cohen's h. The same comparison is reported for scores within ±0.05 of the cutoff; near-cutoff share is diagnostic and not a separate verdict signal.
  • Attribution drift: LightGBM pred_contrib produces TreeSHAP values for at most 5,000 rows per population. Per-feature contribution distributions use KS with adjusted p-values, and mean-absolute-contribution rankings use Spearman correlation.
  • Important set: features are ranked by reference mean absolute TreeSHAP. The smallest prefix reaching 80% cumulative importance is model-important. In paired mode, score and attribution tests use the evaluation set; fit-set contributions used elsewhere can be in-sample.

A similar score histogram does not guarantee stable feature contributions or performance. Conversely, changed scores can reflect legitimate case-mix change rather than worse conditional performance.

Sources: analysis.py; docs/reference.md.

For importance weighting and CBPE, the default material tolerance is a 0.02 absolute AUC drop for binary classification or a 0.02 relative error increase for regression. A performance signal is severe only when the entire 95% CI is beyond tolerance. It is moderate when the point estimate is beyond tolerance, or when the CI crosses the boundary and degradation exceeds half the tolerance. A wide interval alone is reported as imprecision. If estimators disagree, do not quote one as target performance; obtain labels and investigate which assumptions fail.

Aggregation

  • severe — “Different: do not use the model as is” when any counted signal is severe.
  • mild — “Similar: the model can be used (with monitoring)” only when there is no severe signal, at most two moderate signals, and no moderate signal marked important=True.
  • moderate — “Use with caution: mitigation and verification needed” in every other case.

Signals at level info are displayed but excluded from n_severe, n_moderate, and verdict aggregation.

11. CLI and Python API

Single-reference comparison

python -m population_drift compare \
  --train data/labeled.parquet \
  --new data/new.parquet \
  --features-file data/features.txt \
  --categorical country,channel \
  --label-col target \
  --model data/model.txt \
  --missing-sentinels -999 \
  --threshold 0.5 \
  --performance-tolerance 0.02 \
  --n-rounds 30 \
  --out runs/comparison \
  --report runs/report.html

Paired comparison

python -m population_drift compare \
  --train data/fit.parquet \
  --test data/evaluation.parquet \
  --new data/new.parquet \
  --features-file data/features.txt \
  --label-col target \
  --model data/model.txt \
  --n-rounds 30 \
  --out runs/comparison \
  --report runs/report.html

Report regeneration

python -m population_drift.report \
  --comparison runs/comparison \
  --out runs/report.html

Python API

import population_drift as pdrift

config = pdrift.DriftConfig(

    train,
    new,
    features,
    categorical,
    model,
    "target",
    config,
    baseline_dir="runs/baseline",

    fit_set,

    new,
    features,

run_comparison applies one labelled reference to all tests. run_paired_comparison enforces the fit/evaluation assignment shown above. build_baseline creates the source-vs-source null. DriftConfig centralizes inference, cap, threshold, and reproducibility settings.

13. Interpretation and limitations

  • Severe authorizes rejection of unchanged deployment: do not use the model as is; label target data, investigate, and mitigate or retrain.
  • Moderate authorizes only reviewed use: identify the driving signals, test operational impact, obtain labels where material, and define monitoring.
  • Mild says the configured rule found no severe signal, no important moderate signal, and at most two other moderate signals. It does not measure target accuracy and does not establish absence of shift.
  • Baseline limits: exchangeability may be false; a drifting source broadens the null; random partitions do not model temporal or clustered dependence; only 30 rounds give coarse p-value resolution.
  • Power limits: row caps reduce compute but can miss subtle shifts that need more than 2,000 kernel rows, 5,000 SHAP rows, 20,000 correlation rows, 100,000 Isolation Forest rows, or 200,000 classifier rows.
  • Assumption limits: importance weighting, CBPE, and BBSE rely on mutually different conditions. None can detect concept shift without target labels.
  • Selection limits: thresholds are conventions, not learned guarantees. They should be set before inspecting the new population. Repeatedly tuning them to obtain a preferred verdict invalidates the interpretation.
  • Operational limit: “with monitoring” means rerunning this comparison later; the repository does not schedule monitoring.

When the decision matters, label a representative random sample from the new population. That is the direct way to test conditional performance and concept stability.

Sources: README.md; docs/reference.md.

14. References and threshold conventions

  1. Austin, P. C. (2009). “Using the standardized difference to compare the prevalence of a binary variable between two groups.” Communications in Statistics — Simulation and Computation. Source for the 0.10 standardized-difference benchmark.
  2. Cohen, J. (1988). Statistical Power Analysis for the Behavioral Sciences. Effect-size conventions used for SMD and Cohen's h.
  3. Friedman, J. (2003). “On multivariate goodness-of-fit and two-sample testing.” Basis for classifier two-sample testing.
  4. Hanley, J. A., and McNeil, B. J. (1982). “The meaning and use of the area under a receiver operating characteristic curve.” Radiology. AUC/Mann–Whitney relationship.
  5. Lopez-Paz, D., and Oquab, M. (2017). “Revisiting classifier two-sample tests.” International Conference on Learning Representations.
  6. Siddiqi, N. (2006). Credit Risk Scorecards. PSI conventions 0.10 and 0.25.

These cutoffs are conventions, not estimates from the current data. The source-vs-source baseline supplies the data-specific sampling reference.

Source audit and traceability

This assessment was checked against README.md, docs/reference.md, population_drift/analysis.py, population_drift/report.py, and tests/test_comparison.py. Implementation and tests control where prose could be ambiguous. No illustrative algorithm, dependency, or procedure outside the toolkit was added.

The audit identified two caveats worth retaining: single-mode automatic baselines can use a smaller-than-target subset with a warning when the source is too small, whereas paired mode strictly requires n_new + 30; and current metadata does not store a data checksum or git commit. Both are stated above rather than silently normalized away.
