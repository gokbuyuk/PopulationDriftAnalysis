Population Shift Assessment — Technical Reference

Complete description of how the population_drift toolkit decides whether a fitted LightGBM model can be applied to an unlabelled new population: every statistic, the reason it was chosen, its exact implementation, its caveats, and the rule that turns the results into a verdict.

Written against code commit 0d7d0e9 (16 October 2026). Where this document and the code disagree, the code in population_drift/analysis.py is authoritative.

1. Summary

The toolkit compares a labelled reference population (the data the model was built and validated on) with a new, unlabelled population that has the same features. It measures differences in the feature distributions one column at a time, jointly, and in their support. It also measures differences in the model's outputs and attributions, and estimates performance on the new population under three different, explicitly stated assumptions. Each statistic is compared against a size-matched no-shift baseline: the same statistic computed on random splits of the reference, where no real shift exists. The results become a list of signals rated mild, moderate, or severe. A fixed, pre-specified rule turns that list into one verdict.

  • Severe: do not use the model as is. Moderate: use only with review. Mild: no evidence of a shift that the model is sensitive to; monitor.
  • What the run can see: covariate shift, P(x), and, under its assumption, label shift, P(y). What it cannot see: concept shift, P(y|x), and actual accuracy on the new population. Only labels from the new population can test those.
  • Status: implemented and unit-tested on the decision logic. Exercised on synthetic data only. No production population has been scored.

2. Question and identifiability

The decision question is: can the deployed model score the new population without retraining? The new population has the model's input features but no outcome. That limits what can be established.

Shift typeDefinitionIdentifiable without new labels?How the toolkit addresses it
Covariate shiftP(x) changes, P(y|x) unchangedYes. It is a property of x alone.Marginal, joint, support, score, and attribution tests detect it. Importance weighting estimates its effect on performance.
Label (prior) shiftP(y) changes, P(x|y) unchangedEstimable under the stated assumption.BBSE estimates the new prevalence (12.4).
Concept shiftP(y|x) changesNo. Two populations with identical P(x) can have different P(y|x).Not addressed. Requires a labelled sample of the new population.

Measurement boundary. Every performance number for the new population is an estimate under an assumption, never a measurement. A mild verdict means "no evidence of covariate or prior shift that this model is sensitive to". It does not mean "discrimination and calibration carried over". The verdict is a decision rule applied to a list of signals. It is not a level-α hypothesis test that the populations are equal.

4. Data contract and input validation

4.1 What the operator must guarantee

  • Both tables contain the model's input features, with identical definitions, units, encodings, and category codes. The toolkit cannot detect a silent change of definition, for example income reported gross versus net. It sees only that the distribution changed.
  • The feature list is exactly the model inputs. Identifiers, timestamps, row order, batch IDs, the label, and anything derived from the label or the score must be excluded. Otherwise the domain classifier separates the populations trivially, with AUC ≈ 1.
  • The new table is a representative draw of the population the model would score.
  • The model file is the deployed model. --problem-type and --threshold match production.

6. The size-matched no-shift baseline

6.1 Procedure

  1. For round r = 1…R (default R = 30), randomly permute the reference with seed seed + r. The first nnew rows play the new population and the remaining rows play the reference.
  2. Run the full analysis on that pair, with bootstrap and permutation inference switched off (for_baseline). Only point statistics are needed.
  3. Store every comparable statistic in long format. These are the baseline values: how large each statistic gets from sampling noise alone.
  4. For the real comparison, compute the same statistic on reference versus new: the observed value.

6.2 Decision quantities

  • Exceeds baseline: the observed value is strictly greater than the 95th percentile of the baseline values (np.percentile, linear interpolation).
  • Empirical p-value = (1 + number of baseline rounds with a value ≥ the observed value) / (1 + number of rounds). The +1 counts the observed value as one more draw under the no-shift hypothesis, so p is never 0 (Phipson and Smyth 2010). With 30 rounds the minimum is 1/31 ≈ 0.032.
  • Every statistic compared with the baseline is oriented so that larger means more drift: |SMD|, |log variance ratio|, 1 − ρ, 1 − ESS ratio, degradation.

Effective strictness at 30 rounds. With 30 baseline values, the interpolated 95th percentile lies between the 3rd- and 2nd-largest values. "Exceeds baseline" therefore means that at most 2 of the 30 baseline values are at least as large as the observed value, which is equivalent to an empirical p ≤ 3/31 ≈ 0.097. The baseline gate on its own is roughly a one-sided 10% gate. It is tightened by being combined with the significance and effect-size gates. For borderline decisions, increase --n-rounds.

6.3 Why this design

  • Why size-matched: PSI, KS D, Wasserstein, and out-of-fold AUC all shrink as sample size grows. A baseline built at a different size gives the wrong noise level. Size mismatch is therefore checked. A supplied baseline whose subset size is outside 0.5× to 2× of nnew produces a warning, and a baseline built on a different feature set is rejected.
  • Why random splits of the reference: under exchangeability they are draws from exactly the no-shift hypothesis, with the reference's own skew, ties, sparsity, and missingness. No distributional assumption is needed.
  • Why 30 rounds: each round reruns the full analysis, so cost grows linearly with rounds. Thirty is the smallest count that gives a usable 95th percentile and a p-value resolution of 1/31. It is a cost compromise, not an optimum.
  • Why no inference in baseline rounds: only the statistic's distribution is needed. Bootstrap and permutation inside each round would multiply the cost without adding information.

6.4 Assumptions and caveats

  • Exchangeability within the reference. Random splits ignore temporal order and clustering, such as multiple accounts per customer or branch effects. If the reference window itself drifted, the baseline widens and a further shift can look ordinary. Use a reference window over which the model is known to have performed acceptably.
  • Conservative default when a baseline value is missing: if a statistic has no baseline values, the code treats it as beyond the baseline (_beyond_baseline returns True). Missing evidence cannot clear a flag.
  • Not every baselined statistic is used as a gate. AD and CvM statistics, |SMD|, |log variance ratio|, unseen share, missingness-pattern JS, SHAP relative change, the rank-ρ deficit, ESS deficit, and performance degradation are baselined for reporting in baseline_comparison.csv. Which statistics gate which signals is listed in 13.2.

Code: build_baseline, compare_to_baseline, _beyond_baseline, run_comparison, COMPARABLE_METRICS. Tests: add-one p-value, a 95th-percentile exceedance, a metric with no baseline values, and the feature-set mismatch error.

7. Multiple testing

  • Within a test family: p-values are adjusted across features, or pairs, with Benjamini–Hochberg at α = 0.05 (correction_method="fdr_bh"; holm and bonferroni are also available). The families are KS, AD, CvM, χ², missingness z, Spearman pair z, range binomial, and SHAP-contribution KS, each adjusted separately.
  • Why BH: this is a screening problem over many features, and controlling the false discovery rate keeps power where a family-wise correction would not. BH is valid under positive regression dependence (Benjamini and Yekutieli 2001), which is the typical case for correlated features. Benjamini–Yekutieli would be the conservative alternative under arbitrary dependence, but it is not implemented.
  • Global tests: the two kernel tests (MMD and energy) use Bonferroni over the tests that ran (α/2). The domain classifier and the Isolation Forest are single tests.
  • Across signals: there is no correction. The verdict rule tolerates up to two non-important moderate signals before escalating. This is a heuristic allowance for multiplicity, not formal error control. The family-wise false-alarm rate of the verdict has not been calibrated. The only evidence is the synthetic check in §18.

8.2 Mean equivalence (TOST)

Two one-sided Welch t-tests (statsmodels ttost_ind, unequal variance) with margin ±0.10 pooled SD at α = 0.05. equivalent=True is positive evidence that the means are within 0.1 SD. Why: a non-significant difference test is absence of evidence, not evidence of similarity (Schuirmann 1987). TOST is the correct test for claiming similarity. Role: informational. It appears in feature_assessment.csv but does not lower severity, because equal means say nothing about variance, shape, or tails.

8.4 Missingness

  • Per feature: a two-proportion z-test on the missing rate (statsmodels proportions_ztest; p = 1 when both rates are 0 or 1), BH-adjusted, with Cohen's h = 2·asin√pnew − 2·asin√pref as the effect size.
  • Joint pattern: each row's vector of missing indicators is a pattern. χ² and JS distance compare the pattern frequencies, and the 20 most frequent patterns are tabulated. This is informational and not a signal.
  • Why separate from the value distribution: LightGBM learns a default direction for missing values at each split. A change in the missing rate changes how much mass follows that branch even when the observed values are stable. Changes in missingness are also the most common symptom of a pipeline or source-system change.
  • Why Cohen's h rather than the raw difference: the arcsine transform stabilises variance. A move from 1% to 5% (h ≈ 0.25) is treated as more material than 40% to 44% (h ≈ 0.08), even though the raw difference is the same.
  • Severity contribution: |h| ≥ 0.20, adjusted p < α, and beyond the baseline gives moderate. |h| ≥ 0.50 gives severe. A feature's severity is the worse of its distribution level and its missingness level.

9. Joint-distribution tests

9.1 Domain classifier (classifier two-sample test)

Implementation. The target is population membership (reference = 0, new = 1), never the business label. Continuous features enter as numbers. Categoricals enter as native LightGBM categoricals over the union of levels. Missing values are handled natively. Each population is capped at 100,000 rows (max_classifier_rows = 200,000 in total). The model is a LightGBM classifier with fixed hyperparameters: 200 trees, learning rate 0.05, 31 leaves, min_child_samples 20, row and column subsampling 0.8, L2 penalty 1. Scores are out-of-fold from stratified, shuffled 5-fold cross-validation, and the metric is ROC AUC on those scores.

Reported alongside the AUC: a 95% bootstrap CI (200 resamples of the out-of-fold scores within each population, without refitting); a one-sided Mann–Whitney p-value on the fixed out-of-fold scores; a permutation p-value from 20 refits with shuffled population labels, (1 + #null AUC ≥ observed)/21; and gain importance from one refit on all rows, showing which features drive the separation.

Signal: mild if the AUC is within the baseline or ≤ 0.55, moderate if ≤ 0.80, severe above 0.80. The permutation and Mann–Whitney p-values are reported but do not gate the signal. The baseline does that job, matched to nnew.

  • Why a classifier: it detects any difference in the joint distribution that a flexible learner can exploit, including interactions and non-linear combinations (Friedman 2003; Lopez-Paz and Oquab 2017). Using the same model family as the deployed model means it "sees" the kind of structure the business model can use.
  • Why AUC: it is threshold-free and independent of the group-size ratio. Under no shift its expected value is 0.5 whatever the sizes. It also equals the Mann–Whitney probability that a random new row scores above a random reference row (Hanley and McNeil 1982).
  • Why out-of-fold: in-sample AUC rewards memorisation and is above 0.5 even with no shift. Out-of-fold scoring grades each row with a model that never trained on it.
  • Why fixed hyperparameters: tuning to maximise AUC would report the maximum over configurations, which is biased upward, and would need nested CV to stay honest. Fixed, moderate settings make the AUC a measurement rather than the winner of a search.
  • Why the permutation p-value does not gate: with 20 permutations its minimum is 1/21 ≈ 0.048, too coarse to gate at 0.05, and each permutation costs 5 refits. The size-matched baseline answers the more relevant question: is this AUC larger than random splits of the reference produce at this sample size?
  • Why 0.55 and 0.80: these are conventions. 0.80 corresponds to "excellent discrimination" on the Hosmer–Lemeshow scale. Populations that are that separable overlap poorly, which also makes importance weighting unreliable.
  • Caveats: a leaky column (ID, date) pushes the AUC to ≈ 1. Inspect the top gain drivers first. The AUC is a global measure: one materially shifted important feature can leave it near 0.55, which is why the per-feature tests are kept. Gain importance describes this classifier, not the business model, and is not causal.

9.2 Kernel tests: MMD and energy distance

Encoding (shared with the Isolation Forest): continuous features are imputed with the reference median and standardised with the reference mean and SD. Each categorical is one-hot encoded on its 10 most frequent reference levels, with missing as its own level. Rarer and unseen levels encode as all zeros. Each population is capped at 2,000 rows.

  • MMD²: unbiased (U-statistic, off-diagonal) squared maximum mean discrepancy with an RBF kernel. The bandwidth is the median pairwise distance over up to 1,000 pooled rows (the median heuristic). The p-value comes from 100 label permutations with the bandwidth held fixed (Gretton et al. 2012).
  • Energy distance: 2·E|X−Y| − E|X−X′| − E|Y−Y′| on Euclidean distances, with a permutation p-value from 100 permutations (Székely and Rizzo 2013).
  • Signal: moderate if either test has p < α/2 (Bonferroni over the two tests) and its statistic exceeds the baseline. It can never be severe.
  • Why include them: they are model-agnostic. With a characteristic kernel, MMD is consistent against every alternative, so it is an independent cross-check on the tree-based classifier.
  • Why capped at moderate: the cost is O(n²) in memory, which forces the 2,000-row cap and therefore low power. The results also depend on encoding choices: standardisation, one-hot weighting, and median imputation (which hides changes in missingness). They corroborate; they do not decide.

9.3 Dependence structure

  • Scope: continuous features only, up to 20,000 rows per population. Spearman correlations use pairwise-complete observations.
  • Global: the Frobenius norm of the upper triangle of Rnew − Rref, with a permutation p-value from 100 shuffles of the pooled rows.
  • Per pair: a Fisher z test on the two Spearman ρ values with variance 1.06/(n − 3) (Fieller, Hartley and Pearson 1957), BH-adjusted across pairs.
  • Signal: moderate if the global norm exceeds the baseline and has permutation p < α, or if a pair of two model-important features has |Δρ| > 0.20 with adjusted p < α. There is no baseline gate on the pair rule.
  • Why Spearman: trees are invariant to monotone transforms, so rank dependence is the notion that matters to the model. It is also robust to outliers. Why both a global and a per-pair test: a global norm can hide one large change in a pair the model relies on, and one pair can be noise. Box's M was rejected because it assumes normality.
  • Caveats: only pairwise monotone dependence is checked. Dependence involving categoricals and higher-order interactions is left to the domain classifier.

10. Support tests (out-of-distribution)

Tree ensembles do not extrapolate. Beyond the last split threshold, the prediction is constant. Rows outside the training support therefore receive confident-looking predictions with no empirical basis.

10.1 Per-feature range coverage

  • For each continuous feature: the share of new values below the reference 0.5% quantile or above the 99.5% quantile. Under no shift the expected share is 1%. A one-sided binomial test (BH-adjusted) checks for an excess. The share beyond the reference minimum and maximum is also reported.
  • Signal: moderate if a model-important feature has more than twice the expected share outside the range, adjusted p < α, and a share beyond the baseline. Capped at moderate.
  • Why quantiles, not min/max: one training outlier would otherwise define the support, and min/max are the least stable statistics of a sample.

10.2 Joint support: Isolation Forest

  • Up to 100,000 rows per population, using the encoding from 9.2. The reference rows are split 70/30. An IsolationForest with 200 trees is fitted on the 70%. The out-of-support threshold is the 1% quantile of score_samples on the held-out 30%. The share of new rows below the threshold is then compared with 1% by a one-sided binomial test.
  • Signal: mild if within the baseline or below 2%, moderate up to 5%, severe above 5%. The binomial p-value is reported but does not gate.
  • Why the held-out threshold: rows the forest was fitted on look less anomalous to it. Calibrating on unseen reference rows makes the expected share exactly 1% under exchangeability.
  • Why Isolation Forest: a product of per-feature ranges still leaves holes, combinations never observed together. Isolation Forest finds such regions without estimating a density and scales linearly (Liu, Ting and Zhou 2008).
  • Caveats: the results depend on the encoding, and median imputation makes missing values look typical. Missingness is covered by 8.4 instead.

11. Model-centric tests

These tests answer the question that matters for the decision: does the shift reach the model's output? A shift in a region where the model is flat is harmless. A small shift near the cutoff may not be.

11.1 Score distribution

  • Scores are positive-class probabilities (binary) or predictions (regression). KS and PSI are computed on the scores, using reference-score deciles as bins.
  • Signal: mild if neither score PSI nor score KS D exceeds the baseline, or if PSI < 0.10. moderate if PSI ≤ 0.25, severe if PSI > 0.25. This signal is always flagged as model-important, so a moderate score shift on its own prevents a mild verdict.
  • Why: the score is what the business consumes. Score PSI is the standard credit-scorecard monitoring metric. A change in the model's own output is model-relevant by definition.

11.2 Operating point (binary only)

  • Predicted-positive rate at decision_threshold (score ≥ threshold): a two-proportion z-test and Cohen's h. Signal: moderate if |h| ≥ 0.20 and p < α. There is no baseline gate and no importance flag. Capped at moderate.
  • The share of scores within ±0.05 of the threshold is compared with the same test. It is reported only.
  • Why: approval and decline volumes, operational capacity, and loss budgets depend on the rate at the cutoff. When mass sits near the threshold, a small location shift can move that rate substantially with an unremarkable PSI. More borderline cases also mean more expected misclassifications.

11.3 Attribution drift (TreeSHAP)

  • Exact path-dependent TreeSHAP from LightGBM (pred_contrib=True; Lundberg et al. 2020) on up to 5,000 rows per population. For each feature: KS on the contribution distributions (BH-adjusted), mean |SHAP| in each population, and its relative change. Across features: Spearman ρ between the two mean-|SHAP| vectors (requires more than two features).
  • Signal: moderate if ρ < 0.80, or if a model-important feature has contribution KS ≥ 0.10, adjusted p < α, and a value beyond the baseline. The ρ rule has no baseline gate. Capped at moderate.
  • Why: it measures drift through the learned function. A similar score histogram can be produced by different reasons, and changed reasons are an early sign that the model is operating in a regime it was not validated for.

11.4 Model-important features

  • Features are ranked by mean |TreeSHAP| on the reference (the evaluation set in paired mode). The important set is the smallest prefix whose cumulative share reaches 80% (important_feature_cumulative_share). Features with zero attribution are never important.
  • Why 80%: it is a Pareto-style convention that separates the features driving the output from the long tail. Why SHAP rather than split gain: SHAP attributions are consistent and measured in output units. Gain is biased towards high-cardinality features.
  • Without a model, every feature is treated as important. This is conservative: any moderate feature then prevents mild.
  • Caveat: in single mode on training rows, the attributions are in-sample. Path-dependent TreeSHAP also reflects the training data's cover statistics.

12. Label-free performance estimation

Each estimator answers "how would performance change?" under a different assumption. None measures performance on the new population.

12.1 Reference calibration (binary, needs labels)

Brier score. Expected calibration error (ECE) over 10 equal-width bins, weighted by bin share (Guo et al. 2017). Calibration slope and intercept from an effectively unpenalised logistic regression (C = 10⁶) of the label on logit(score) (Cox 1958). A reliability table on score deciles is used for the plot. Role: always info. If ECE > 0.05, the CBPE signal is downgraded to info. Why: CBPE is valid only for calibrated probabilities, and calibration on the reference is the only part of that assumption that can be checked.

12.2 Importance-weighted performance (needs labels and the domain classifier)

  • Weights: the domain classifier's out-of-fold probability p for each reference row gives w = p/(1 − p) × nref/nnew, where the n's are the row counts the classifier used and p is clipped to [10⁻⁶, 1 − 10⁻⁶]. Weights are capped at their 99th percentile, and the number of clipped weights is reported.
  • Overlap diagnostic: Kish effective sample size, ESS = (Σw)²/Σw² (Kish 1965), and the ESS ratio = ESS/n. Signal: mild above 0.50, moderate from 0.10 to 0.50, severe below 0.10. There is no baseline gate.
  • Metrics: AUC, Brier, and log loss (binary) or RMSE and MAE (regression), weighted on the labelled reference rows the classifier used. The comparison value is the unweighted metric on the same rows. The CI is a percentile bootstrap (200 resamples of rows, keeping their weights). The signal uses AUC (binary) or RMSE (regression).
  • Why it works: under covariate shift, Enew[loss] = Eref[w(x)·loss] with w = pnew(x)/pref(x) (Shimodaira 2000; Sugiyama et al. 2007). By Bayes' rule, the classifier's odds times the size ratio estimate that density ratio. Out-of-fold probabilities keep the weights from being inflated by overfitting. Clipping trades a little bias for much lower variance.
  • Caveats: the method requires P(y|x) to be unchanged and the populations to overlap. A low ESS means a few rows dominate. The bootstrap CI holds the weights fixed and so ignores uncertainty in the classifier: it is too narrow. In single mode on training rows, both the reference metric and the estimate are in-sample.

12.3 Confidence-based performance estimation (CBPE, binary only)

  • Computation: expected ROC AUC if each label were Bernoulli(score), computed exactly over sorted unique scores (ratio of expectations, self-pairs removed, ties counted as 0.5). Expected accuracy, precision, and recall at the threshold are also reported.
  • Like-for-like reference: degradation = CBPE(reference scores) − CBPE(new scores). The realised reference AUC and the gap between realised and estimated AUC (source_calibration_gap) are reported as a sanity check. Why: a calibration defect biases CBPE on both populations in the same way, so comparing like with like cancels it rather than mistaking it for a shift.
  • CI: a bootstrap over new rows only (200 resamples). The reference CBPE is treated as fixed, so the interval ignores reference-side variability.
  • Signal: rated on AUC with the tolerance rule in 12.5. It becomes info when reference ECE > 0.05. CBPE also runs without labels, in which case no ECE check is possible and the signal is never downgraded.
  • Caveats: it assumes calibration carries over and P(y|x) is unchanged. It cannot see regions where the model is confidently wrong. The concept is the one popularised by NannyML, re-implemented here without that dependency.

12.4 Black-box shift estimation (BBSE, binary, needs labels)

  • Hard predictions at decision_threshold. On the reference: Cij = P(ŷ = i, y = j). On the new population: μi = P(ŷ = i). The class weights are w = C−1μ, and the new prior is qj ∝ wj·Pref(y = j), clipped at 0 and renormalised (Lipton, Wang and Smola 2018). The condition number of C is reported, since C is ill-conditioned when the model is near random or the threshold is extreme. The CI is a bootstrap resampling both populations (200).
  • Signal: moderate if the 95% CI of the new prevalence excludes the reference prevalence. Capped at moderate.
  • Why: in credit, default rates move with the economic cycle while borrower profiles given the outcome may be comparatively stable, which is the label-shift case. Under pure label shift, ranking (AUC) is preserved but calibration and threshold metrics are not, and the estimated prior is what would be used to recalibrate the intercept or the threshold.
  • Caveats: under covariate shift this is the wrong model. There is no effect-size gate, so at large n a negligible prior change is flagged moderate. Always read the size of the estimated change.

12.5 Performance signal rule

The tolerance τ is performance_tolerance: 0.02 absolute AUC for binary models, or 0.02 × |reference RMSE| (relative) for regression. With bound = reference − τ when higher is better (reference + τ otherwise):

  • severe: the whole 95% CI is worse than the bound.
  • moderate: the point estimate is worse than the bound, or the CI crosses the bound and the point degradation exceeds τ/2.
  • mild: otherwise. A wide CI that merely crosses the bound is reported as imprecision, not as degradation.

Tested cases, with reference AUC 0.80 and τ = 0.02: estimate 0.70 [0.68, 0.72] → severe; 0.77 [0.76, 0.79] → moderate; 0.795 [0.785, 0.805] → mild.

12.6 When the estimators disagree

Importance weighting assumes covariate shift. BBSE assumes label shift. CBPE assumes calibration and an unchanged P(y|x). Disagreement is evidence that at least one assumption fails. Report the estimates side by side and treat the question as inconclusive. Do not quote the most favourable one, and do not average them. The resolution is a labelled sample.

13.3 Verdict

  • severe — "Different: do not use the model as is" — if any counted signal is severe.
  • mild — "Similar: the model can be used (with monitoring)" — if there is no severe signal, there are at most two moderate signals, and no moderate signal carries the important flag.
  • moderate — "Use with caution: mitigation and verification needed" — otherwise.
  • info signals are shown but excluded from the counts and the rule.

Why this rule: any severe signal is a sufficient reason not to deploy unchanged. A small number of moderate signals on features the model barely uses is expected even under no shift (see the synthetic check in §18), so it should not block deployment. A moderate signal that touches what the model uses (important features or the score itself) does block it.

Worked examples (from the unit tests):

  1. One feature with PSI 0.30, adjusted p 0.001, beyond baseline → the feature is severe → verdict severe.
  2. The same PSI 0.30 but within the baseline, or with adjusted p 0.50 → the feature is mild.
  3. Unseen levels in 2% of rows, plus a domain AUC of 0.70 beyond the baseline, neither flagged important → 2 moderate → verdict mild.
  4. The same, plus a significant, beyond-baseline MMD → 3 moderate → verdict moderate.
  5. Reference ECE 0.90 → the calibration signal is info, not counted → verdict unchanged.

Signals are correlated. One underlying change can raise several signals. A missingness jump on an important feature shows up as both "feature drift" and "missing-value rates". A score shift typically comes with positive-rate and SHAP signals. The "at most two moderates" count treats them as independent. When reviewing a moderate verdict, group signals by their root cause.

Code: assess_features, interpret_results, _performance_signal. Tests: test_assess_features_*, test_interpret_results_*, test_performance_signal_*.

16. Running the analysis

Paired mode (recommended)

python -m population_drift compare \
  --train data/fit.parquet --test data/evaluation.parquet --new data/new.parquet \
  --features-file data/features.txt --categorical country,channel \
  --label-col target --model data/model.txt --missing-sentinels -999 \
  --threshold 0.35 --performance-tolerance 0.02 --n-rounds 30 \
  --out runs/comparison --report runs/report.html

Single mode

python -m population_drift compare \
  --train data/labeled.parquet --new data/new.parquet \
  --features-file data/features.txt --label-col target --model data/model.txt \
  --n-rounds 30 --out runs/comparison --report runs/report.html

A pre-built baseline can be passed with --baseline in single mode only. Regenerate a report with python -m population_drift.report --comparison runs/comparison --out runs/report.html.

Python API

import population_drift as pdrift

config = pdrift.DriftConfig(problem_type="binary", decision_threshold=0.35, seed=42)
decision = pdrift.run_paired_comparison(
    fit_set, evaluation, new, features, categorical, model, "target", config,
    output_dir="runs/comparison", n_baseline_rounds=30,

decision["verdict_level"]   # "severe" | "moderate" | "mild"

run_comparison is the single-mode equivalent. build_baseline builds a standalone no-shift baseline, and population_drift_analyzer runs the tasks without a baseline or verdict. Custom thresholds: DriftConfig(thresholds=pdrift.Thresholds(psi_major=0.20)).

Reproducibility

  • Recorded automatically: seed, full configuration, row counts, feature types, failed tasks, and the versions of Python, numpy, pandas, scipy, scikit-learn, and LightGBM. Dependencies are pinned in requirements.txt.
  • Not recorded, so record them manually with every archived run: a checksum of each input file (for example shasum -a 256), the code commit (git rev-parse HEAD), the model file checksum, and the exact command line.
  • LightGBM is not run with its deterministic option. If bit-identical reruns across machines or thread counts are required, verify by rerunning, and consider --n-jobs 1.
  • Failed tasks: a task that raises is logged, recorded in metadata["failed_tasks"], and copied into decision.json warnings. Its signal is then absent. Missing evidence is not evidence of stability, so check this list before accepting any verdict.

  • Not unit-tested: the numerical correctness of each statistic against independent implementations. Most statistics delegate to SciPy, statsmodels, scikit-learn, and LightGBM. The custom pieces are PSI, expected AUC, BBSE, the quadratic permutation tests, and the weighting.

  • Not yet done: a calibrated false-alarm rate under the operating configuration, power against known shift sizes, and any run on production data.

19. Limitations and known gaps

Identifiability

  • Concept shift and actual performance on the new population cannot be assessed without new labels.
  • The performance estimates rest on mutually incompatible assumptions. None of them can be verified on the new data.

Design

  • The baseline assumes exchangeability within the reference and ignores temporal and clustered dependence.
  • There is no error control across signals. Correlated signals are counted as independent.
  • The thresholds are conventions. Changing them after seeing results invalidates the verdict.
  • There is no segment-level analysis (product, channel, region, protected groups) and no time-series monitoring. "With monitoring" means a later rerun; the repository does not schedule one.
  • Selection effects are out of scope. If the labelled reference is a selected population, for example approved and booked accounts, while the new population is through-the-door applicants, the comparison mixes credit-policy effects with population shift.

Implementation

  • Importance-weighted CIs ignore uncertainty in the classifier. CBPE CIs ignore reference-side variability. Both are too narrow.
  • BBSE, the positive rate, the SHAP rank-ρ rule, the dependence pair rule, ESS, and unseen levels have no baseline gate. BBSE also has no effect-size gate.
  • Distance-based tasks (MMD, energy, Isolation Forest) impute medians and one-hot encode only the top 10 levels, so they are blind to missingness and to rare-level changes.
  • SciPy caps the AD p-value at 0.001 at the low end. Row caps limit the power of the kernel, correlation, SHAP, Isolation Forest, and classifier tasks on large populations.
  • In single mode, the auto-built baseline shrinks its subsets when the reference is smaller than 2 × nnew. It warns, but does not stop.
  • Thresholds are not exposed on the command line.
  • Dataset checksums and the code commit are not recorded automatically.

20. Frequently asked questions

Statistical design

Why not simply apply PSI/CSI with the 0.10 / 0.25 rule?
PSI is biased upward at small n, depends on binning, and has a different natural spread for every feature. A fixed cutoff therefore over-flags small samples and skewed or sparse features, and under-flags large ones. The 0.10 / 0.25 values are kept as effect-size floors, but a flag also requires statistical significance and exceeding the size-matched no-shift baseline.
What exactly is the "no-shift baseline", and why random splits?
It is the distribution of each statistic over 30 random splits of the reference, each split sized like the new population. A random split of one population has no real shift by construction, so these values show how large each statistic gets from sampling noise alone, at the right sample size, without assuming any distribution.
Isn't requiring significance, baseline exceedance, and effect size all together too lenient?
It is designed to avoid flags that would not change a decision. Within each gate the statistics are joined by OR (any of KS, AD; any of KS D, PSI, Wasserstein; any of PSI, KS D, SMD), which keeps the analysis sensitive. Shifts that are real but small are still visible in feature_assessment.csv. They just do not escalate.
What is the false-alarm rate of the verdict?
It has not been calibrated. The verdict is a decision rule, not a level-α test. The one synthetic check (10 no-shift pairs) gave no severe and 3 moderate verdicts. Treat a single weak moderate as a review item.
Why are numeric columns with 10 or fewer distinct values treated as categorical?
KS-type tests assume continuous distributions. With heavy ties their p-values are invalid and D becomes hard to interpret. χ² and Cramér's V are the correct tools for discrete supports.
Why are KS and AD used for significance, but CvM is not?
KS is most sensitive near the centre and AD in the tails, so between them they cover the shift shapes that matter for risk models. Adding CvM as a third route would mostly add false alarms. It is reported for review.
Why doesn't a successful equivalence test (TOST) clear a feature?
TOST establishes that the means are within 0.1 SD. A feature can have equivalent means and a changed variance, tail, or shape, all of which matter to a tree model.
Why Spearman rather than Pearson for dependence?
Trees are invariant to monotone transforms, so rank dependence is what the model can exploit. Spearman is also robust to outliers and heavy tails, which are common in financial features.

Machine-learning methodology

Can the domain classifier leak or overfit?
It never sees the business label. Its scores are out-of-fold, so no row is scored by a model trained on it. Its hyperparameters are fixed, so its AUC is not the best result of a search. The real leakage risk is in the feature list: identifiers, dates, or score-derived columns separate the populations trivially. Check the top gain drivers first.
Why is the classifier's permutation p-value not used in the verdict?
Twenty permutations give a minimum p of 1/21 ≈ 0.048, too coarse to gate at 0.05, and each permutation is 5 refits. The size-matched baseline answers the more relevant question: is this AUC larger than random splits of the reference produce at this n? The permutation p-value is still reported.
Why does feature importance come from TreeSHAP on the reference?
Importance has to describe the deployed model as validated. On the new population, importance would itself be affected by the shift. In paired mode it uses the evaluation set, so it is out-of-sample.
How far can the importance-weighted performance estimate be trusted?
Only under covariate shift (P(y|x) unchanged) with adequate overlap. Read the ESS ratio first: below 0.10 the estimate rests on a handful of rows. Its CI holds the weights fixed and is therefore too narrow.
How does CBPE here relate to NannyML, and what if the model is miscalibrated?
It is the same idea, re-implemented. Degradation is computed like-for-like, CBPE on the reference versus CBPE on the new population, so a shared calibration bias cancels. If reference ECE exceeds 0.05, the CBPE signal is downgraded to info, because the assumption is visibly violated.
When should BBSE be believed?
When the change is plausibly in outcome prevalence alone. In credit, this is a cyclical shift in default rates with stable borrower profiles given the outcome. If the feature tests show covariate shift, BBSE's assumption is violated and its estimate should be disregarded.
What if the three performance estimates disagree?
Disagreement means at least one assumption fails. Report them side by side as inconclusive, then label a sample. Do not quote the best estimate or average them.

Banking and governance

Does this satisfy ongoing-monitoring requirements under model risk management (for example SR 11-7)?
It provides documented, pre-specified, reproducible evidence on population stability and expected model behaviour without outcomes, which is one component of ongoing monitoring. It does not replace outcome-based back-testing (discrimination, calibration, and default-rate accuracy on realised outcomes). Archive decision.json, metadata.json, data checksums, and the code commit with each run.
Is per-feature PSI the same as a Characteristic Stability Index (CSI)?
Yes. The per-feature PSI on reference deciles is a CSI. The score PSI is the classic scorecard stability index. Both are reported, with bootstrap CIs and baseline positions added.
Our labels exist only for approved accounts. Does that matter?
Yes. Selection (reject inference) is not modelled. Compare like with like: if the new file is through-the-door applicants, use a through-the-door reference for the feature tests. Note that label-based estimates (calibration, weighting, BBSE) then describe the approved population only.
How should macroeconomic or through-the-cycle effects be treated?
Choose a reference window that spans the conditions over which the model was validated. A downturn in the new period will typically appear as label shift (BBSE) and score drift. Whether that is acceptable is a policy decision, not a statistical one.
Can it check fairness or segment-level stability?
Not directly. Run the same comparison per segment (product, channel, region), each with its own baseline, and expect lower power at small n. Fair-lending and disparate-impact analysis is out of scope. Protected attributes should not be added as features unless they are model inputs.
What does each verdict authorise?
severe: no unchanged deployment; investigate, label a sample, and adapt or retrain. moderate: deployment only after reviewing the driving signals, an operational impact check (for example of approval rates), and a labelling and monitoring plan. mild: deployment with a scheduled rerun. The model owner and validation function make the final decision. The toolkit supplies the evidence.
How large should the labelled sample be if the verdict is not mild?
The toolkit does not compute this. One rule: choose n so that the 95% CI half-width of the AUC is at most the tolerance, using the Hanley–McNeil standard error SE² = [A(1−A) + (n₁−1)(Q₁−A²) + (n₀−1)(Q₂−A²)] / (n₁n₀), with Q₁ = A/(2−A) and Q₂ = 2A²/(1+A). For low default rates, the number of defaults n₁ drives the requirement.

Operational

Can the thresholds be changed for our portfolio?
Yes, through the Python API (Thresholds, DriftConfig), before the new data is examined. They are recorded in metadata.json. Changing them after seeing results invalidates the decision.
What happens if part of the analysis fails?
Structural problems stop the run with a descriptive error. A failure in one analysis task is logged, recorded in failed_tasks, and shown in decision.json warnings, and the other tasks still run. A verdict with failed tasks is incomplete.
How long does a run take?
It has not been benchmarked. Cost grows with the baseline rounds (each reruns all tasks without inference), the classifier permutations (20 × 5 refits), and the bootstrap count. The row caps bound the quadratic and SHAP tasks.
Which reference should be used?
In paired mode, the model's fit set plus an out-of-time labelled evaluation slice the model never trained on, drawn from a period over which it performed acceptably. Single mode on training data is acceptable only for a first look.
